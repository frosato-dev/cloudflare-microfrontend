# Deploy to Cloudflare Workers

## Prerequisites

- Node.js + pnpm installed
- Cloudflare account created at [dash.cloudflare.com](https://dash.cloudflare.com)

## Authentication

### Local dev (browser OAuth)

```bash
npx wrangler login
```

Opens browser, authorizes wrangler against your CF account. Verify with:

```bash
npx wrangler whoami
```

### CI / headless

Set `CLOUDFLARE_API_TOKEN` env var. Create the token in CF dashboard → Workers & Pages → API Tokens → use the "Edit Cloudflare Workers" template.

## Account targeting

If your CF login has multiple accounts, wrangler prompts interactively on first deploy. To skip the prompt:

```bash
export CLOUDFLARE_ACCOUNT_ID=<your-account-id>
```

Find your account ID in the CF dashboard sidebar (Workers & Pages → Overview).

> Adding `account_id` directly to `wrangler.jsonc` works but is not recommended for shared repos.

## Deploy

From the monorepo root:

```bash
pnpm run deploy
```

This runs `pnpm run build && framework-cli deploy`, which:

1. Builds all packages (`pnpm -r run build`)
2. Generates app wrangler configs with auto-discovered service bindings
3. Collects all built assets into a unified `dist/static/` directory
4. Deploys each worker sequentially via `npx wrangler deploy`

## What gets deployed

5 Cloudflare Workers:

| Worker             | Type      | Public                    |
| ------------------ | --------- | ------------------------- |
| `fragment-header`  | Fragment  | No (service binding only) |
| `fragment-footer`  | Fragment  | No (service binding only) |
| `fragment-product` | Fragment  | No (service binding only) |
| `front-office`     | Shell app | Yes                       |
| `back-office`      | Shell app | Yes                       |

- Shell apps have **service bindings** to all fragments (auto-generated by `framework-cli`)
- Shell apps serve static assets via the Workers Assets binding (shared `dist/static/`)
- Fragments are self-contained — no asset bindings, no public routes

## Custom domains / routes

Shell apps are publicly accessible at their `*.workers.dev` URL by default. To bind to a custom domain, add `routes` to the app's `wrangler.jsonc`:

```jsonc
{
  "routes": [{ "pattern": "example.com/*", "zone_name": "example.com" }],
}
```

Fragment workers don't need public routes — they're accessed only via service bindings from shell apps.

## Verify

```bash
# check auth
npx wrangler whoami

# after deploy, check worker URLs in CF dashboard
# or visit https://front-office.<your-subdomain>.workers.dev
```

To connect to personnal account and not use BackMarket:

- env -u CLOUDFLARE_API_TOKEN npx wrangler login
- env -u CLOUDFLARE_API_TOKEN pnpm run deploy
