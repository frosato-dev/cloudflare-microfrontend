# Worker Internals

Source: `framework/src/worker/shell.ts`, `framework/src/worker/fragment.ts`

## `createShellWorker(config)`

Returns a Cloudflare Worker `{ fetch(request, env, ctx) }`.

### Config Shape

```ts
interface ShellWorkerConfig {
  routes: AppRoute[];
  middleware: Record<string, { default: Middleware }>;
  layouts: Record<string, { default: Component }>;
  document: { title: string; baseStyles?: string };
}
```

These are populated by the virtual server entry (see [Vite Plugins](vite-plugins.md)).

### Request Flow

1. **Manifest lazy-load**: on first request, fetch `manifest.json` from `env.ASSETS` binding, cache in closure
2. **Debug detection**: check `__debug` and `__debug_nocache` cookies
3. **Page cache check**: `caches.default.match(request)` — skip if debug or nocache
4. **Fragment fetcher construction**: for each fragment:
   - Derive binding key: `FRAGMENT_${id.toUpperCase()}`
   - Build URL with route props as query params
   - Fragment cache check: `caches.default.match(cacheKey)` (with `__fragment` namespace)
   - Fetch via service binding: `env[bindingKey].fetch(url)`
   - Cache write: `ctx.waitUntil(cache.put(...))`
5. **Debug wrapping**: if debug, wrap fetcher with `wrapFetcherWithDebug()` for timing metadata
6. **`handleRequest()`**: delegates to SSR pipeline (see [SSR Rendering Pipeline](ssr-rendering-pipeline.md))
7. **Page cache write**: if `s-maxage` present, collect streamed chunks via `TransformStream`, cache on flush
8. **`s-maxage` stripping**: remove from client-facing `Cache-Control` to prevent Cloudflare edge from buffering the stream

### Fragment Cache Key

```ts
const cacheUrl = new URL(url.toString());
cacheUrl.searchParams.set('__fragment', fragmentId);
const cacheKey = new Request(cacheUrl.toString());
```

The `__fragment` query param namespaces fragment cache entries so they don't collide with page cache.

### Stream-Through Page Caching

```ts
const passthrough = new TransformStream({
  transform(chunk, controller) {
    chunks.push(chunk);       // Collect
    controller.enqueue(chunk); // Pass through to client
  },
  flush() {
    const body = new Blob(chunks);
    ctx.waitUntil(pageCache.put(pageCacheKey, new Response(body, response)));
  },
});
return new Response(response.body!.pipeThrough(passthrough), ...);
```

The client gets the streamed response immediately. The cache write happens in `flush()` after the stream completes, inside `ctx.waitUntil()`.

## `createFragmentWorker(render, cacheControl)`

Minimal worker — calls render, returns JSON:

```ts
function createFragmentWorker(render: RenderFn, cacheControl: string) {
  return {
    async fetch(request: Request) {
      const result = await render(request);
      return new Response(JSON.stringify(result), {
        headers: {
          'Content-Type': 'application/json',
          'Cache-Control': cacheControl,
        },
      });
    },
  };
}
```

The `render` function is generated by the virtual server entry:
```ts
async function render(request) {
  const props = config.props ? config.props(request) : {};
  const app = createSSRApp(App, props);
  const html = await renderToString(app);
  return { html };
}
```

### Response Shape

```json
{ "html": "<header class=\"header\">...</header>" }
```

Optional `css` field for scoped styles (if the fragment build produces inline CSS).

## `s-maxage` Stripping

```ts
function stripSMaxAge(cc: string): string {
  return cc.replace(/,?\s*s-maxage=\d+/g, '').replace(/^\s*,\s*/, '');
}
```

Why: Cloudflare's edge treats `s-maxage` as a signal to buffer the entire response before sending. Stripping it from the client-facing headers preserves streaming while still using `s-maxage` internally for the Workers Cache API write.
